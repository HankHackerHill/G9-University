# G9 MENTOR desktop — the 16 screens (Ledger 2, 2026-11-13)

Source of truth for routes and titles: `apps/desktop/src/app/router.tsx` (`SCREENS`). Layout, components and states of every screen: `docs/ui/handoff.md` §11 and the design system `docs/ui/design-system.md`. Words: `docs/ui/ux-copy.md`. Every screen renders without Tauri and without a model (R-002, A09) against the deterministic mock transport (`apps/desktop/src/ipc/transports/mock.ts`), and `apps/desktop/src/app/screens/screens.test.tsx` exercises every screen in two conditions: fixture data, and a backend that answers `RESOURCE_UNAVAILABLE` for everything.

## Conventions shared by all screens

| Concern | Rule | Where |
|---|---|---|
| Provenance | Every displayed text says how far it can be trusted: Verified (operator or system-deterministic record), Advice (model or skill output; advisory only), Proposed (awaiting an operator decision). The backend's exact name is in `title`. | `components/Badge.tsx`, `lib/copy.ts` |
| Model down | Where model output would be, `ModelUnavailable` says "<what>: no model" with the backend's reason. Planning, notes, timers and reviews do not depend on a model. | `components/Panel.tsx` |
| Missing data | `NoData` ("No data", "Not enough data") with the reason, `role=status`. No placeholder numbers, no estimates, never a zero. | `components/Panel.tsx`, `components/Stat.tsx` |
| Errors | `ErrorDisplay` maps all 13 `ErrorCategory` values to a title, guidance, severity and a retry affordance for retryable categories; the backend's message and code stay visible under it. One per failed read. | `components/ErrorDisplay.tsx`, `lib/error-text.ts` |
| Warnings | The backend's disclosures of every read and action on a screen are merged (`mergeWarnings`) and shown (`Warnings`), in the operator's words (`lib/copy.ts`). A standing fact (`QUIET_WARNING_CODES`: a plan from a version that is not canonical) is a quiet note with the backend's sentence, not an alarm, and is not announced. | `components/Warnings.tsx`, `lib/warnings.ts` |
| Identity | The UI never sets an actor. `ClientCommandMeta` has no `actor`; the mock refuses meta that carries one (`meta.actor_not_accepted`). | `ipc/client.ts` |
| Clock | "Today" is `system.status.clock` (backend clock and IANA zone), never `Date.now()` in the UI. Durations are backend values; the UI never derives elapsed time from wall-clock subtraction. | `app/hooks/useToday.ts` |
| Names | A title, file name or label is one line of visible text; the backend refuses others (`input.name_not_printable`) and the mock mirrors it. | `lib/text.ts` |
| Approvals | A protected operation answers `APPROVAL_REQUIRED`; the screen shows an `ApprovalCard` (the voucher) under the control that asked; Approve asks the native confirmation window, which names the record (ADR-0014 addendum 2); Apply re-issues the same operation with the approval, which is used once and expires after 10 minutes (ADR-0015). | `app/hooks/useApprovalFlow.ts`, `components/ApprovalCard.tsx` |
| Offline | `system.status.network.egress_allowed === false` is shown as a lamp in the shell, on Mission Control and on Research Center, as the operator's setting, not a fault. | `layout/Shell.tsx` |
| Theme | 21 themes (Ledger plus 20); grammar of standing, three type voices, high contrast and persistence: `docs/ui/design-system.md`. | `app/theme/` |
| Markdown | Rendered only through `renderMarkdown` (marked, then DOMPurify allow-list): no script, style, iframe, object, svg, img, form, no `on*`, `style`, `class`, `id`, `data-*`, `aria-*`, and no link at all (a web or mail address is shown as text to copy); the window itself refuses navigation away from the application. | `lib/markdown.ts`, `components/MarkdownPreview.tsx`, `src-tauri/src/lib.rs` |

Global keyboard map: `Ctrl K` opens search and commands; `?` opens the ledger key; `Tab` goes through the skip link, the search field, the 16-link navigation (`nav[aria-label=Screens]`, `aria-current=page` on the active link), the status lamps, the appearance controls, the day rail and `main`; Escape closes a composer or an overlay. Every action is a native button, link or form control.

## Authority boundaries visible in the UI

- State-machine tables in `src/lib/state-machines.ts` mirror `crates/g9-domain/src/state.rs` (edge counts asserted in tests). They only enable or disable controls. The backend (or the mock, standing in for it) refuses illegal edges with `PRECONDITION_FAILED <machine>.illegal_transition`; the UI shows that error.
- `useApprovalFlow` never fabricates approvals: it lists them from the backend and re-issues the original command with the approval id. The webview asks; only the native confirmation grants (ADR-0014).
- The mock transport is a labelled test double (`SystemStatus.transport === 'mock'`; the shell shows a "Synthetic data" banner). Its fixture is `apps/desktop/src/fixtures/curriculum-week3.json`. It mirrors the backend's checks (hash binding, single use, 10-minute expiry, names, classification), with two known gaps: `assessment.submit` ignores `notes` and `assessment.begin` does not infer retakes.
