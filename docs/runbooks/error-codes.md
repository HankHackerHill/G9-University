# Error-code catalogue

Generated by `python3 -I scripts/gen_error_codes.py --write`; do not edit by hand. Every error that reaches the operator is a `G9Error` (`crates/g9-domain/src/envelope.rs`): one of the 13 closed categories and a dotted code. Sources: the production Rust of `crates/*/src`, `apps/cli/src` and `apps/desktop/src-tauri/src` (test items removed) and the TypeScript of `apps/desktop/src` (tests and the mock transport excluded). Operator actions and written meanings: `docs/runbooks/error-codes.actions.json`.

`python3 -I scripts/gen_error_codes.py` (no flag) exits 1 when this file differs from a regeneration (a code without a row, a row without a code), when the actions file names a code the source does not have or quotes a document that does not say it, and when `docs/ui/ux-copy.md`, `docs/runbooks/first-run.md`, `docs/runbooks/backup-restore.md`, `docs/curriculum/promotion.md` names a code the source does not have.

## Method and blind spots

| Item | Detail |
|---|---|
| Extraction | Rust is lexed (strings decoded, comments dropped). `G9Error::new` is the root sink; a function that passes a parameter on as the code or the category becomes a sink too (fixpoint over the call graph), and every call of a sink with a known code is a row. `let code = e.code(); match e { A => ctor(code) }` gives only the codes of `A` |
| Test code | `tests/` directories are not read; `#[cfg(test)]` and `#[test]` items, `#![cfg(test)]` files and the files of `#[cfg(test)] mod x;` are removed before extraction (2 files removed whole) |
| Operation names | `notes.create` and the like are first arguments of `op(..)` in `crates/g9-app/src/ops.rs` and never reach a code position, so they are not rows (53 operation names read) |
| Unresolved, fails the check | a code position the analysis cannot evaluate: a closure parameter, a collection element, a call that matches several functions, a method that passes a code parameter on (calls `x.m(..)` are not followed) (0 now) |
| Not seen | `fn code` in a trait impl (only inherent impls are read); a `G9Error` decoded from stored JSON (an idempotent replay returns a code the source raised before); macros other than `format!` and `json!` that build the code |
| Wrapping | `G9Error { details, ..e }` and an `e.code` passed on keep an existing code and add no row |
| Unsupported, fails the check | a `G9Error { code: .. }` struct literal or an assignment `x.code = ..` in production code: the analysis reads constructors and code functions only, so such a code would be missing; build the error with a constructor |
| Frontend | object literals with `category` and `code` only; the mock transport (`ipc/transports/mock*.ts`) is a development double and is not catalogued |
